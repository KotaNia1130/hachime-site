# 折角翻頁修改與驗收

分支：`fix/corner-page-turn`。未合併或發布。

## 修改方案與實作

- 開啟從右下角、返回從左下角先掀起小角，約 180ms 後帶動整頁，總長約 760ms。紙背加入紙紋、折線明暗及投影。
- 改用瀏覽器動畫播放預先計算的紙面裁切，停止載入 StPageFlip；沒有每幀 JavaScript 幾何計算。
- 正面使用與原頁一致的快照，保留照片、陰影、左側目錄及捲動位置。紙背沒有文字，正面不鏡像。
- 連點時目的頁立即更新，目前紙面持續翻完後顯示最後選擇；不排隊延遲導覽，也不中途撤掉紙面。
- 調整視窗、離開分頁、改用減少動態效果時清理動畫。不支援動畫的瀏覽器直接切頁。

## 驗收方式

執行 `npm test`，涵蓋原有六套功能測試與新增的 `paper-visuals`。

新增畫面測試在 1440px 與 390px 視窗比對原頁和翻頁第一格，涵蓋首頁、新手內文、圖鑑轉飼養筆記及捲動後返回；容許少量字緣反鋸齒差異，但會拒絕超過 0.1% 的像素有明顯變色。另檢查小角先掀起、正反方向、文字不鏡像、快速切換目的地及減少動態效果。

原有測試繼續涵蓋 320–1440px 排版、拖曳、縮放、頂部標籤、左側目錄、章節捲動、瀏覽器返回、31 個圖鑑入口、輪播、引導與購物車。

效能量測使用真實時間；畫面比對使用可控制的動畫時間，兩者分開執行，不把測試時鐘當成實際流暢度。

## 測試結果

原有六套功能測試通過；新增畫面測試在修正媒體偏好事件的等待時序後單獨複測通過。靜態檢查 62 個本地引用通過，未捕獲 JavaScript 例外。

同一雲端 Linux Chromium 的真實時間複測，正常桌面首次開啟的 95 百分位幀間隔從約 66.7ms 降至 33.3ms，最長間隔從約 100ms 降至 33.4ms；返回的 95 百分位從約 50.1ms 降至 33.4ms。正常手機尺寸各操作約 16.7–16.8ms。這些數字涵蓋點擊後的取樣區間，不是純動畫平均 FPS。

4 倍 CPU 降速時仍觀察到首次開啟約 100–150ms 的單次停頓，主要動畫期間多數間隔維持 17–33ms。測試包含開啟、返回、重開、捲動後返回及快速反向操作，結束後均無殘留轉場。

## 待人工確認

- 目前採用折角與明暗模擬紙張彎折；角度、紙背質感、速度仍需以實際觀看確認是否符合預期。
- 測試環境為雲端 Linux Chromium，手機為模擬視窗；Windows 高倍率縮放、實機手機及其他瀏覽器尚需驗收。
- 慢速 CPU 下，建立紙面快照時仍可能短暫停頓；不保證所有裝置都固定 60fps。
